# Постановка и план работы

## Цель и критерии

Команда **MISIS x MEPhI DRM TM** участвует в [Molecular Activity Prediction](https://www.kaggle.com/competitions/molecular-activity-prediction-hack). Нужно предсказать `SI VACV` по SMILES. SI — отношение CC50/IC50. Метрика Kaggle — MSE в исходных единицах SI, меньше лучше. Submission: CSV с ровно двумя колонками `index,SI VACV` и одной строкой на каждый объект test. Дедлайн: **8 ноября 2026 года, 09:00 МСК**. Публичная таблица считается примерно по 30% теста, окончательная — по оставшимся 70%.

Для защиты нужны сильный результат, ссылка на GitHub, исходный код выгрузки и проверки данных, код обучения и проверки модели, база `SMILES,IC50,CC50,SI,DOI` и запуск, создающий сравнимый submission. Место в топ-5 не гарантируется кодом и зависит от результатов других участников.

## Правила данных

В исходном Kaggle train 320 строк, в test 597 строк. Поля train: `Title,CC50_uM,IC50_uM_VACV,SI VACV,SMILES,strain,Culture`; test содержит те же поля без SI и с `index`. Файл образца на сайте назван `sample_submit.csv` (в описании написано `sample_submission.csv`). Названия колонок и порядок строк брать из фактического образца.

**Организатор прямо запрещает использовать `CC50_uM` и `IC50_uM_VACV` для построения модели и предсказаний.** Эти поля служат только для аудита. Вход модели — SMILES и вычисленные из структуры признаки. `Title`, `strain`, `Culture` используются для аудита, сопоставления записей и группировки в проверке; возможное применение их как признаков требует отдельной проверки правил и оценки риска утечки.

Первичный аудит: все 320 train-строк имеют SI, 81 значение равно ровно 10000; именно у этих 81 строк пустой IC50. Есть одно значение SI выше 10000; максимум 36066.667, медиана 20.2605. Девять строк test имеют исходный SMILES, совпадающий с train; после нормализации RDKit получено 29 общих канонических структур. В test 588 уникальных текстовых SMILES. Нужно выяснить смысл значения 10000; нельзя без доказательства объявлять его измерением или заглушкой.

Не обучаться на колонках запрещённых измерений, их пропусках, вычисленных отношениях или результатах закрытого теста. Не переносить опубликованные SI в тест без проверки правил и происхождения. Сходство структур и внешние данные проверять на пересечения с валидационными частями.

## Открытые данные

Основной источник — [ChEMBL API](https://chembl.gitbook.io/chembl-interface-documentation/web-services/chembl-data-web-services): activity, assay, document, molecule. Поиск по vaccinia/VACV/VV, описаниям экспериментов, публикациям и типам `IC50`, `CC50`, `Ratio CC50/IC50`. Фильтра только по вирусной мишени недостаточно: SI может иметь иную аннотацию мишени. Проверенный пример: [антивирусный assay CHEMBL4700293](https://www.ebi.ac.uk/chembl/api/data/assay/CHEMBL4700293.json), [цитотоксичность CHEMBL4700294](https://www.ebi.ac.uk/chembl/api/data/assay/CHEMBL4700294.json), [SI CHEMBL4700295](https://www.ebi.ac.uk/chembl/api/data/assay/CHEMBL4700295.json) связаны документом CHEMBL4699424, DOI `10.1039/d0md00108b`. Это подтверждает структуру данных, но не означает автоматическую пригодность всех записей.

Второй источник при наличии дополнительных пригодных записей — [PubChem BioAssay PUG REST](https://pubchem.ncbi.nlm.nih.gov/docs/bioassays). Проверять дубли между базами. Для каждого измерения сохранять URL, ID записи, исходное число и единицы, знак `=`, `<` или `>`, публикацию/DOI, молекулу, вирусный штамм, клеточную линию, тип опыта, дату выгрузки и причину включения/исключения. Отдельно хранить SI, прямо опубликованный источником, и SI, вычисленный из совместимых IC50 и CC50. Не считать EC50 тождественным IC50. Не превращать цензурированные измерения в точные. Учитывать флаги ChEMBL о валидности и повторных публикациях: [описание проверок](https://chembl.gitbook.io/chembl-interface-documentation/frequently-asked-questions/chembl-data-questions).

## Моделирование и оценка

1. Нормализовать структуры RDKit, записать ошибки разбора и правила обращения с солями и стереохимией.
2. Вычислить Morgan fingerprints и молекулярные дескрипторы. Первая модель — среднее SI, далее Ridge, ExtraTrees/RandomForest, CatBoost и модель сходства. Нейросеть только при доказанной пользе и доступных ресурсах.
3. Зафиксировать разбиения с группировкой одинаковых молекул. Отдельно проверить новые химические каркасы и публикации. Внешние копии объектов валидации исключать из обучающей части каждого разбиения.
4. Сравнивать по MSE в исходной шкале SI. Логарифмирование цели, веса внешних данных и ансамбль оценивать только по сохранённым валидационным предсказаниям.
5. Разбирать ошибки по диапазонам SI, особенно у значений 10000 и выше. Публичный лидерборд использовать для ограниченной финальной проверки, учитывая его меньшую долю теста.
6. Выпустить детерминированный `submission.csv`: ровно 597 строк в порядке `sample_submit.csv`, числовые конечные прогнозы, без пропусков, точные заголовки.

## Требуемая структура результата

Планируемые компоненты: `src/` с выгрузкой, валидацией, признаками, обучением и предсказанием; `data/` с очищенной открытой базой и её метаданными; `configs/` с параметрами; `reports/` с проверками и сравнением моделей; `tests/` для критичных инвариантов. Исходные файлы соревнования, ключи и учётные данные не публиковать автоматически. README должен содержать одну последовательность команд от установки окружения до `submission.csv`, версии зависимостей, seed, контрольные суммы фиксированного снимка данных и пример метрики.

## Порядок и сроки

- Первые 3–5 часов: аудит, рабочая базовая модель, первый CSV и первая отправка.
- До 12-го часа: сборщик открытых данных, первичная база, проверка качества.
- 12–24-й час: сравнение моделей, проверка эффекта внешних данных, выбор ансамбля.
- 24–30-й час: чистый повторный запуск, GitHub, отчёт и материалы защиты.
- Последние 6 часов до дедлайна: резерв, проверка сдачи и финальной отправки.

Оценка активной работы: 20–28 часов в пределах 36-часового окна. Первый приоритет — воспроизводимый результат и корректные данные; на улучшение MSE направить оставшееся время.
