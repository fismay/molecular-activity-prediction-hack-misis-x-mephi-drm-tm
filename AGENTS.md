# Инструкции для агентов

Цель репозитория — воспроизводимое предсказание `SI VACV` для [соревнования Kaggle](https://www.kaggle.com/competitions/molecular-activity-prediction-hack). Перед работой прочитать [PROJECT_BRIEF.md](PROJECT_BRIEF.md), особенно запрет на признаки и требования к источникам.

1. Работать в `main` небольшими проверяемыми изменениями. После законченной небольшой задачи запускать относящиеся к ней проверки, коммитить и отправлять в `origin/main`. Перед отправкой проверить `git status`, diff и отсутствие ключей, токенов и случайных файлов.
2. Не использовать `CC50_uM`, `IC50_uM_VACV`, их отношение, признаки их пропусков или информацию из закрытых ответов теста в модели. Признаки извлекать из SMILES. `Title`, `strain`, `Culture` по умолчанию использовать только для аудита и группировки проверки.
3. Внешнюю базу строить с доказуемым происхождением каждой строки: URL, ID измерения, DOI при наличии, исходные единицы и знак отношения. Нельзя соединять IC50 и CC50 по одной только молекуле без проверки условий опыта. Не выдавать нижние/верхние границы за точные значения.
4. Разделять данные по нормализованной молекуле; проверять пересечения с внешней базой внутри каждого fold. Оценивать MSE в исходной шкале SI. Фиксировать seed, версии библиотек, параметры и сохранённые разбиения.
5. Не объявлять `SI=10000` достоверным биологическим измерением или ошибкой до выяснения происхождения. Сохранять исходные значения и документировать все преобразования.
6. Перед выпуском `submission.csv` сверить 597 строк с `sample_submit.csv`, порядок `index`, точные колонки `index,SI VACV`, отсутствие NaN/Inf. Проверить, что изменение запрещённых колонок не меняет прогноз.
7. Каждое улучшение сравнивать с текущим воспроизводимым baseline на одинаковых split. Не выбирать решение по одному публичному баллу Kaggle. Записывать результат эксперимента и команду воспроизведения.
8. Не публиковать учётные данные, ключи API и исходные файлы приватного соревнования. Открытую собранную базу и код публиковать только с проверенным происхождением и разрешёнными лицензиями.

При конфликте между локальными заметками и актуальными правилами Kaggle сначала проверить правила и зафиксировать решение в документации. Поддерживать README так, чтобы новый участник мог создать базу, обучить модель, проверить её и получить submission последовательностью команд.
